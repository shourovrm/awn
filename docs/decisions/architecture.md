# Architecture

## Current state
- Modules: :app, :core:ui, :core:data, :tracker (JVM only), :player, :feature:read, :feature:listen, :feature:recite, :feature:learn. Feature modules depend on the core modules, :player and :tracker; :feature:duas also depends on :feature:recite and on :feature:read (line view and word card). :feature:read depends on no other feature module, so there is no cycle. :app depends on all.
- :core:ui: theme package (Color, Type, Spacing, Theme, FieldColors, ColourMode) holds every token; components AwnButton, AwnSwitch (thin rail), AwnPlayerDock, AwnIconButton, AwnTopBar (extends behind the status bar; use `AwnTheme(barBehindStatusBar = true)`), AwnChoiceDialog (index only), and the settings kit: `AwnSettingsPage`, `SettingsRows` (link, info, switch, stepper, group heading), `AwnChoiceRow`, `AwnPackRow`, `AwnConfirmDialog`, `AwnSearchField`, `SettingRowKeys` (keys search opens). Icons are Material Symbols XML copied per module (`ic_ui_*`, `ic_app_*`).
- Gate tests in :core:ui scan every src/main .kt file in the repo: no .dp other than 0, 1, 2, 4, no .sp, no Color(0x outside the theme package; no quoted text in Text(, contentDescription =, label =, placeholder =; no banned words in strings.xml outside names starting notice_.
- Colour modes: Awn (paper, green bars, ochre), Light (white, grey bars, green), Dark (#121212), Black (#000000). `ColourSettings(day, night, followDevice, manualNight)` resolves to a `ColourMode`; `LocalColourMode` is set at the app root. `awnFieldColors(field, mode)`: Awn keeps one colour per field, the other modes draw every field on the page colour (Green is the raised bar colour). `AwnFieldColors` holds the four highlight fills and `barBackground`/`onBar`. The Quran screen's day/night button calls `rememberNightToggle(preferences)`, which flips `manualNight` and stops following the device.
- :core:data: WordKey(surah, ayah, wordPosition), pack models (Credit, PackEntry with format_version and sha256, PackManifest), Packs.usable (format_version at or below the supported one), Room AwnDatabase v1 with a bookmark table, no destructive fallback, MigrationTest checks every exported schema migrates to current.
- :tracker contracts: TrackerInput.nextBlock() returns 16 kHz mono floats or null at end; PhonemeSource.accept/finish return new PhonemeEvent(symbol, onsetSeconds, probability); Tracker works on reference word indexes (not WordKey, which is Android-only); WordState Neutral, Confirmed, Tentative, Wrong, Hidden.
- SherpaPhonemeSource wraps OnlineRecognizer (Zipformer2 CTC, greedy_search, endpoint off, 80-dim 16 kHz features) and reports only tokens not reported before. Blank token is <blank>.
- Language: AppCompat per-app locales (`AppCompatDelegate.setApplicationLocales`, app/language/); MainActivity is an AppCompatActivity under Theme.AppCompat.Light.NoActionBar, and the manifest enables `AppLocalesMetadataHolderService` autoStoreLocales, so Android 8 to 12 store and apply the locale and Android 13+ hands it to LocaleManager; either way the activity is recreated. `generateLocaleConfig` builds locales_config from values/ and values-bn/. Below Android 13 only activities follow it: services (media notification) use the phone language.
- First launch: `firstLaunchStep(noticeAccepted, languageChosen)` gives ChooseLanguage or Done; a user with the notice accepted is Done, so upgrades skip the language screen. `LanguageScreen` (app/onboarding/, colours `welcomeColours`) previews its own text in the highlighted language by replacing LocalConfiguration and LocalResources; Continue writes `language_chosen` first, then applies the locale (the recreate would cancel a later write).
- Notice, colour choices and surah name meaning live in DataStore (app/AppPreferences); the old `theme_preference` (Light, Dark, System) is read as colour settings until the first write. Status-bar icons are set by `AwnTheme` from the colour behind the bar: `enableEdgeToEdge()` chooses them once from the device night setting, which left white icons on cream (defect 8). The notice is not a launch step: `LearnNoticeGate` shows `NoticeScreen` (short text in the app language, strings notice_learn_*) in place of Learn until accepted; About shows the full English, Bangla and Arabic text (non-translatable notice_english, notice_bangla, notice_arabic; the Arabic is the maintainer's wording).
- :app wiring: `AwnApplication.onCreate` builds one `AwnServices` (hand-written holder, no DI): CoreData, ExoAudioPlayer, OkHttpAudioDownloads, learn's ProgressEvents, ReadDependencies, settings stores. `AwnViewModelFactory` builds the view models; `ReciteViewModel` holds the `RecitationSession` and the chosen range.
- Navigation: the app starts on `tabs` (`TabsHost`: Quran, Learn, Hifz over `AwnTabBar`, selected tab held in `AwnNavigation`, each tab's saved state kept by `SaveableStateProvider`, Back on Learn or Hifz selects Quran). The Quran screen `quran?page=&surah=&ayah=` opens above the tabs with no bar; `openQuran` pops to `tabs` first so Back always returns to the tab, and `onOpenIndex` selects the Quran tab and pops; `onBackWhenIdle` calls `NavController.leaveQuran` (`QuranFromDuas.kt`): it pops to `tabs` (the tab the user came from stays), except when the Quran screen was opened from a Dua through `openQuranOverDuas`, which keeps the Duas entry on the stack and Back pops only the Quran screen. `showPageWords` (Quran menu, Hifz part menu) remembers the Quran page and tab as `PageWordsReturn` and shows the Learn page words; Back from them (`LearnScreen.onPageWordsBack`) calls `leavePageWords`, which selects that tab and reopens the page. The Quran tab is `QuranTabScreen` (app/index: continue card, Today, snippet, Surahs and Juz lists chosen by Show, Go to page, juz rail), Bookmarks is its own screen, then Search (`CoreData.search`), Settings hub with section pages, Notice, Credits; Listen, Recite, Reciters and Downloads stay until the maintainer removes them. Every NavHost passes the four `ScreenTransitions` (a 200 ms slide, mirrored in RTL; Navigation Compose's default 700 ms fade made Back slow) and the manifest opts out of predictive back (its back-to-home animation shrank the window); NavTransitionsTest checks both.
- Settings is a hub of nine rows in three groups (Quran: Quran page, Audio; Practice: Recite and Hifz, Learn; App: Language, Colours, Downloads, Backup, About) with a search field (see design-system.md). Routes: `settings/quran`, `settings/audio?row=&manager=` (manager=true opens the audio downloads manager, used by Downloads' Reciters row), `settings/recite`, `settings/learn`, `settings/colours`, `settings/storage`, `settings/backup`, `settings/about`, `settings/prints` (the Mushaf chooser), `settings/list/<kind>`. Search: `SettingsSearchIndex` lists each setting with its label and value names in English and Bangla, `searchSettings` matches every word; a result navigates to `settings/<page>?row=<key>` and the row scrolls into view (the Language result opens the hub dialog, key `hub.language`). Colours, Downloads (route `settings/storage`), Backup, About, Recite and Hifz (Memorised after, Follow pace, Hide words, First-letter hint) and Learn (reminder, lesson language) are in :app; Quran page (merged Mushaf and Reading, one Screen rotation row that sets both orientations, Surah name meaning passed in from :app), Audio and the lists call the feature modules. Language is an `AwnChoiceDialog` (English, বাংলা in their own script) that calls `AppCompatLanguageApplier`. Tab plug-ins live in `TabSlots` (app/tabs): `hifzTab: @Composable (TabActions) -> Unit` and `todayProviders: List<TodayProvider>`; a `TodayProvider` returns a `TodayItem(title, detail, icon, onOpen)` or null from composition, at most two rows show and none means no section; the Learn row caps today's ayahs at 10. `LocalNavigationBarBackground` makes `AwnTheme` pick navigation-bar icon colours for the tab bar colour.
- The speech model, tokens and reference phonemes are not in the APK: `SpeechModelStore` downloads them to filesDir/models (see data.md). Every recite entry goes through `ReciteBarOrDownload` in :app (`reciteEntryStep`: the notice card until `noticeAccepted`, then `SpeechModelCard` until the files are there, then the bar); Settings > Downloads has a Recitation checker row with size and Remove.
- Fonts: Roundo and Noto Serif Bengali are not bundled; every screen uses the platform sans-serif until the files are added. Type.kt now has six sizes (12 caption added).

## Gotchas
- sherpa OnlineRecognizer takes android.content.res.AssetManager in its constructor; :tracker compiles against com.google.android:android:4.1.1.4 only for that type.
- Bangla notice text is the agent's translation; have a Bangla reader review it.
