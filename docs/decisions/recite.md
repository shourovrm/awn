# Recite

## Current state
- Recite lives on the Quran screen. `ReciteController` (one per process, created in `AwnServices`) owns the `RecitationSession`, `SpeechPreparation` and `ReciteSettings`. API: `reciteFrom(AyahRef)` loads that ayah to the end of its page (script V2), `reviseAt(AyahRef)`, `grade(AyahGrade)`, `exit()`, `isActive`, `isRevising`, `revisionRemaining`, `speechState`, `setSpeed`, `setHideWords`. Optional constructor arguments: `gradeSink`, `revisionQueue` (`RevisionQueue.dueAyahs()`), `onOpenAyah`.
- Reciting continues past the page: when fewer than 15 words are left to recite, the session asks the controller for the ayahs of the next page that has any (`ayahsOnPageAfter`) and appends them to the tracker (`Tracker.append`) without a reset, across page and surah boundaries. An empty answer (end of the Quran) stops asking. The session loop runs the read itself (no dispatcher switch), so tests stay synchronous.
- `ReciteBar(controller, onExit)` fills the `reciteBar` slot: ONE row of 44 dp buttons (`ReciteBarControls`): close, speed popup, hide-words switch, [while words are hidden: show next word, show ayah], listen, microphone (stop square while listening). No status line. Show next word takes two taps per word: the first draws the word's first letter centred in its hidden box on the page (`RecitationSession.hint`, `rememberReciteHintLetters`, `PageDecorations.hintLetter`), the second shows the whole word; the Settings row "Show first letter first" (`hintEnabled`) turns the letter step off. `ReciteStrip` sits above the bar only while there is something to say (`reciteStripMessageOf`: microphone permission, grade prompt, what the run found, revision count, failed start) and holds the Review entry after a run that flagged words. Preparing still replaces the row with progress and Close. Under the row, when an ayah is finished in hide-words mode: four grade buttons Easy, Good, Hard, Forgot, one tap each; the grade the recitation earned is filled (a 2 by 2 grid from font scale 1.3). Colours come from `ReciteBarColors`, so Awn, Light, Dark and Black all work; `ReciteBarLayoutTest` checks 360 dp at font scale 2.0 in every mode.
- While audio plays during recite mode, `QuranScreen` shows the audio bar (previous, next, reciter, repeat, mic at the end; the mic calls `resumeReciting`) and keeps the recite bar composed but tucked away. The controller follows audio from any source (`followAudioWhileListeningOnward`) when it plays an ayah past the one being recited, so the microphone goes on there; the reveal buttons also load the next page.
- Grades: `HifzRules.suggestedGrade(missedWords)` is Good for 0, Hard for 1, Forgot for 2 or more; Easy is only ever chosen by the user. A recited ayah is sent to `ProgressEvents.hifzCompleted` as before (learn rates it the same way) and the prompt carries the suggestion; revealing any word of the ayah sends nothing automatically and the prompt has no suggestion. `RecitationSession.grade` calls `gradeSink(ayah, grade)`; :app maps it to `LearnProgress.gradeAyah`, which replaces the automatic rating.
- Revision: `reviseAt(ayah)` reads the due ayahs from `RevisionQueue`, turns hide words on (also saved), loads from the ayah and sets `isRevising`. After each grade the run moves to the next due ayah after it (else the first before it): it calls `onOpenAyah(next)` and loads it, unless it is already loaded further on. When none is left `isRevising` turns false and recite mode stays.
- `rememberReciteWordStates(controller)` returns `Map<WordKey, WordState>` for the page and now covers appended words too; revealed words are Neutral (shown, no colour), unheard words Hidden in hide-words mode. `rememberReciteCurrentAyah(controller)` and `rememberReciteCurrentWord` give the word the user is on (it moves back while the tracker reports a repeat); the lists scroll to it within the page.
- Speed is strictness (2026-10-25): the bar's speed popup offers Slowest, Normal and Fastest (0, 0.5, 1) and the Settings slider stops at the same three positions; `TrackerConfig.fromSpeed` maps them to Lenient, Normal and Strict (tracker.md).
- No automatic page turn while reciting (2026-10-25): `FollowRecitation` no longer follows the expected word, so a slip the tracker reads as a jump cannot carry the user away. The controller keeps the open page (`pageScript` page of the run's first ayah, of a fresh load after listening, or set by Next page); when the current word is on a later page (its own page: an ayah can run over a page break, read from the next page's layout), `nextPageAyah` is set to the first ayah starting on that page (else the word's ayah) and the strip shows "Next page" (`RECITE_BAR_NEXT_PAGE_TAG`), which calls `onOpenAyah` and moves the open page. Only that tap or the user's swipe turns the page; a focused mistake still turns to its word.
- `stopMicrophone()` (the bar's and the Hifz bar's microphone while listening, the corner button) keeps every mark like `pauseMicrophone()`; both bars use it too when the app goes to the background (ON_STOP) and before Hifz plays audio, so no bar calls `session.stop()` (KeepRecitedProgressGateTest). `ayahToListenTo()` is suspend: with every loaded word done it gives the ayah after the last loaded one.
- `pauseMicrophone()` (Listen, or any playback while reciting) calls `RecitationSession.pauseForListening()`: the next Start keeps every mark and continues from the next expected word (`Tracker.continueFrom`, new phoneme times); a plain Stop then Start, a new `load` or `reset` start fresh.
- The session runs input, phoneme source and tracker on one daemon thread; the tracker is touched only under a lock. Every run (stop, pause, background) ends with `Tracker.closePending()` after `source.finish()`, so a word held for its last consonant turns green before `continueFrom`. `load(List<AyahRef>)`, `unload()`, `stop()` keeps results, `start()` after a run clears them, `reset()` clears and returns to Idle. Ayah results are keyed by surah and ayah, since appended words can cross a surah.
- The speech model runs in the `:speech` process: `SpeechService` (app/services) holds one `SherpaRecognizer` (~144 MB native) and its streams; `RemoteSpeech` binds it, loads the model there while parsing the reference JSON here, and sends 100 ms blocks over synchronous binder calls (`SpeechProtocol`; ~1.5 ms per block on top of ~10 ms decoding). Unbinding ends the service, which kills its process, so everything the model used goes back. `AwnApplication` builds no services in that process. `SpeechPreparation` keeps state (Idle, Preparing, Ready, Failed) and the generation counter as before. Tap to Ready: 2.9 s (in-process it was 2.3 s).
- Review card (`ReciteReviewCard`, replaced the modal sheet): a non-modal card above the bar in the same column, so the Quran screen measures both and keeps the page clear; field colours, so dark at night. It lists `flaggedReviews(reviews, wordProblems)` (every flagged word in reading order; a mispronounced word has its Pronunciation or Duration findings), with Listen, Previous/Next, close and "Experimental feedback on likely mistakes".
- Focused mistake: `ReciteController.focusedWord` (`focusWord`, `clearFocus`) is the word under review. The review button focuses the first flagged word, Previous/Next and a tap on a flagged word on the page focus another; the card shows while it is set. Cleared on close, exit, new load, microphone start, and when the word stops being flagged. The Quran screen reads it through `QuranScreenSlots.reciteFocusedWord`, turns to it, rings it and writes it back with `onReciteFocusWord`.
- Audio in the bar (`ReciteAudioState` from `PlaybackState`, `ReciteListening.kt`): the headphones button calls `listenOnward()` (see Listen onward); `listenToAyah()` still plays one ayah, or just the focused mistake's word when the reciter has word timings (`hasWordTimings`), and is what the review card's Listen uses. While audio is not Idle the headphones become Pause/Resume, a Stop button (`stopListening()`) and a 2 dp progress line show, hint and review hide. The microphone stays enabled and calls `resumeReciting()`; the microphone never restarts by itself, and `Start` after an ordinary stop clears results. `reciteFrom` and `reviseAt` stop the audio first. The bar is ochre in every colour mode (`ReciteBarColors.reciting()`), the microphone/Stop button sits at the end like the audio bar's microphone, and the close button stays at the start (the only way out when the microphone is off). Review sits on a second row because six buttons fill 360 dp.
- Listen onward (`ListenOnward` rules, 2026-10-22): `ReciteController.listenOnward()` pauses the microphone and plays from the ayah the user is on with no end ayah (to the surah end) and the player's repeat setting; `isListeningOnward` is true until `resumeReciting()` (stops the audio, goes on at the ayah that was playing, or after the last played when the audio had ended, then starts the microphone) or `stopListening()` (audio only). `RecitationSession.continueAt(ayah)` makes the next continuing start pick up at that ayah's first word; words before it that were not recited are `listenedIndexes` (passed, drawn plain, never reported), and when the first confirmed word after resuming is in a later ayah the expected ayah's findings are dropped too. An ayah not loaded (audio ran past the page) is loaded fresh.
- `ReciteSettingsPage(settings)` is for the Settings hub. Old `ReciteScreen`, `ReciteRangePicker`, `ReciteWords` and `ReciteSettingsScreen` were removed with the Recite route.

- Speech model stays loaded 2 min after close (`SpeechPreparation.releaseAfterGrace`, cancelled by `prepare()`), released at once by `ReciteController.onLowMemory()` (AwnApplication.onTrimMemory >= RUNNING_LOW). The bar shows only "Preparing…" + progress + Close until `SpeechState.Ready` (`reciteBarMode`). `RecitationSession.wordProblems` feeds the word card (`WordProblem`: Skipped "Missed", DifferentWord "Another word", Mispronounced "Mispronounced").
- Three outcomes on the page: green Confirmed, yellow `WordState.Mispronounced` (the tracker confirmed the word but it has a Substitution event or a non-Ok madd; `ReviewRules.problemsByWord` decides and the session publishes it in `wordStates`), red Wrong (missed or another word). Tentative (word still being recited) and `WordState.Unread` (passed over by a jump ahead: not recited, not a mistake, hidden in hide-words mode) have no fill; an ayah with an Unread word gets no Hifz grade. A red word said right later (`TrackerEvent.Corrected`) is green with an outline on the Mushaf page (`PageDecorations.correctedWords`), listed in review as Corrected (`ReviewFinding.Corrected`, `WordProblem.Corrected`) and not counted. Hifz counts (`PracticeMistakes`, `suggestedGrade`) use Skipped and WrongWord only: a mispronounced word is not a Hifz mistake, because the sound and madd checks are advisory and a clean Husary recitation still gets 2 yellow words in 563.

## Open items
- Phone check: speech preparation time on every recite start and heap after exit; Next page when recitation crosses a page (the open page is per `pageScript` V2, not the user's print, and a hand swipe does not move it); the reveal and grade icons and the bar height with three rows.
- A rotation removes the bar and so stops reciting (`onDispose` calls `exit()`), which now also unloads the model; the next recite waits ~5 s again.
- Any failure to build the phoneme source shows "Can't use the microphone"; a separate line would help.
- Revision does not start the microphone by itself (permission and intent); the user taps it once after each jump.
- Compose tests need `@Config(sdk = [34])`: Espresso fails on the newer SDK (InputManager.getInstance).

## Gotchas
- Copy gate flags any `label = "` in Kotlin; build labels outside the call.
- Detekt ReturnCount and LongParameterList are suppressed with reasons where guards or collaborators are the point.
- A `withContext` inside the session loop makes the unconfined test dispatcher return early: ten tests failed until the extension read ran inline.

## Tried / rejected
- Model in the app process plus Runtime.gc() after release: PSS stayed +54 MB after close (native +38, speech library code +17); hence `:speech`.
- sherpa provider "xnnpack" (as recite_quran uses): same ~10 ms decode per block, load 2.8 s instead of 2.0 s.
- Text "Review" label under each ayah, then per-ayah icon button: replaced by one review button in the bar.
- Voice-activity gate on the microphone: the model emitted 0 phonemes on 26 synthetic noises, so it would only risk cutting quiet recitation.
- Grades committed only when the user taps (no automatic rating): a silent session would lose every ayah the user forgot to grade; the automatic rating is kept and replaced on a tap.
- CI hung 45 min: tests that never called finishPreparing left a load blocked on a Dispatchers.Default thread (2 on the runner); ControllerFixtures now closes fixtures and tests run with a pool of 2. Stopping the session between the phase check and the mic opening left the mic open; fixed in stop().
