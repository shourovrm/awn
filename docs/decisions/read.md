# Read (:feature:read)

## Current state
- Entry points: `QuranScreen(dependencies, slots, modifier, target)` with `QuranScreenSlots` (contract in docs/redesign.md) and `QuranTarget.Page | Ayah`; `ReadingSettingsPage`, `MushafSettingsPage` and `PackListPage(kind)` for the Settings hub. :app wires the slots in `QuranRoute`.
- `QuranViewModel` holds one state: current page, `jumpToken` (jumps bump it, swipes do not, so the pager moves at once in every view), bars, selection (`selection` first ayah, `selectionEnd` last of a dragged range), panel, recite mode, popups, playing ayah and page, `isFollowing`, `isAudioIdle`, font status. The playing word is a separate `playingWordPosition` flow so a tick never changes the state.
- Two views, saved in `ReadSettings.pageView`: Mushaf and LineByLine (the old Translation and Word by word lists merged); the view button switches them and Back never changes it. Old stored "Translation"/"AyahList"/"WordByWord" migrate to LineByLine, with the word-by-word tick on only for the last.
- List views build `PageContent` per page: surah band, a centred Basmalah when `Chapter.bismillahPre` (no chip, no selection), then ayah blocks.
- Title surah: the first surah that starts on the page, else the one that continues; `titleSurahNumber` (title) and `headerSurah` (page frame) apply the same rule.
- Top bar right side: view, layers (LineByLine only: ticks for Arabic, each installed translation by name, transliteration, word by word; the last tick cannot be removed), day/night, text size, settings, overflow (Search, Go to page, Bookmark this page, Rotate screen, Learn). Bars fade in 120 ms; panel and popups appear and close at once. Above font scale 1.3 the buttons move to a second row under the title.
- Bars show for 2 s (`BARS_REVEAL_MS`) when the screen opens, whatever the entry, then hide; a manual toggle or Back cancels that timer, so a bar the reader showed never hides itself. A tap toggles on finger-up; no gesture on the screen listens for a double tap (`InteractionBudgetTest` scans for it).
- Back order is `QuranViewModel.onBack`: popups, word popup, panel, selection, recite mode, bars, then the host leaves. `BackHandler` is enabled only while there is something to close. A page tap (`onPageTapped`) closes the word card, else the ayah bar (not while the panel is open), else toggles the bars; a word tap clears the selection, so only one shows.
- Text size is one step per layer (`arabicSizeStep`, `translationSizeStep`, `transliterationSizeStep`, `wordByWordSizeStep`, 0 to 7 = 0.85 to 1.6, default 3); the popup shows a row per visible layer in LineByLine and the Arabic row only in Mushaf, which moves `mushafSizeStep` (9 steps, 0.7 to 2.0 times the default size, default step 3 = 1.0, `TextScale.mushafScaleOf`; stored under `mushaf_size_step_v2`, the old key's 1 maps to 1.15). The popup has no hint line.
- The screen opens above the tabs; the page the Quran tab's continue card opens is the resume point below, and page numbers in the tab's lists come from `IndexLoader.loadContent(script)` in the user's print (IndoPak falls back to V2; search results still use V2).
- Resume point (`ResumeTracker`): a swipe or volume-key turn is saved 1.5 s after the pager settles and at once on stop; a lookup (search, bookmark, Go to page, index, panel arrows, playback turn) is saved only if the reader stays 1.5 s, and a lookup still pending at stop is dropped. It is stored as the page number through `recordPageOpened`; all prints have the same 604 pages, so it survives a change of print. Pages read are separate: `ProgressEvents.pageOpened` after 20 s on the page while the screen is started, once per page in a row.
- `open` reads the saved settings first, so every entry (resume, bookmark, search, notification, index) opens in the saved view and print; the screen shows nothing until they are known.
- Playback following: `isFollowing` is on at the start of a playback. A pager or list drag turns it off; arriving on the playing page by any route (swipe back, back-to-playing control) turns it on; going to another page while audio plays turns it off. While on, the pager turns to the playing ayah's page and lists scroll to it only when it is not fully visible, leaving 5 % of the list height above it. `BackToPlayingButton` shows while audio plays and following is off. The playing-ayah fill cross-fades over 500 ms (`PlayingFadeState`); each page gets only the marks that fall on it (`highlightsFor`), so a tick recomposes one page.
- Recite following: `followRecitation(WordKey)` (slot `reciteCurrentWord`, the tracker's next expected word, not the audio) finds the word's page from the layouts, so an ayah over a page break turns at the break. `decideReciteFollow` stays when the word is on the shown page; a neighbouring page turns with the animated pager (`animatedTurnToken`), a longer way jumps. A pager or list drag, Go to page or a volume turn sets `isReciteFollowPaused`; reciting a word on the shown page clears it, `enterReciteMode` resets it. In the lists the bottom padding while reciting is the measured height of the bottom stack (`listContentPadding`, from `onSizeChanged` in `QuranContent`), and a tail spacer of one list height after the last item lets the last ayahs rise to the top; the old fixed 72 dp padding left the last ayahs "visible" under the 2 to 3 row bar, so nothing scrolled. The Mushaf page reports the recited word (`MushafPage.trackedWord`, `onTrackedWordBounds`, page coordinates) and `barShiftTarget` slides the page up by `shiftToClearAudioBar` with the measured bottom stack as clearance, so the bar never covers the word being recited; `PageDecorations.focusedWord` draws a ring (`focusedWordRect`; list cells get a fill and a border).
- Mistake focus: slots `reciteFocusedWord` and `onReciteFocusWord`. A tap on a flagged word (in `reciteWordProblems`) calls `onReciteFocusWord` and opens no word card (the Mushaf tap also calls `ignoreNextPageTap`); a focused word replaces the expected word for page turning (`followRecitation(word, ignoresPause = true)`, so a hand swipe does not block it), as `currentAyah` for the lists and as the tracked word for the Mushaf shift. The word card keeps its `problem` line but nothing passes one now.
- Volume keys turn pages only while audio is Idle or Error; otherwise they are not consumed and change the volume.
- `MushafPage(layout, chapters, fontFamily, plainFamily, decorations, showPageInfo, sizeFactor, barInsets, revealGradually, onWordClick, onAyahLongPress)` is the stateless page, called only from `quran/MushafAdapter.kt`. A tap anywhere toggles the bars (the page consumes the tap-up, no parent toggles twice); a 500 ms long press anywhere selects the nearest ayah (`PageGeometry.nearestAyahAt`: the ayah under the point, else the nearest line's nearest token), dragging extends it to a range, lifting ends it. `onSelectionBounds` reports the first-line and whole-selection rectangles in page coordinates. `layoutPage` (PageGeometry.kt, pure, tested) places words: the font size is the largest at which the widest line fits (capped at 0.8 of a slot), lines at least 80 % of the block are justified, shorter lines centred.
- Pages 1 and 2 are a centred block: slot height 1.2 x normal, banner centre at 27 % of the height, block width 0.9, no justification.
- Glyph pages draw each word's code with the page font, and the end sign is `AyahEnd.glyphCode` (last word code + 1; V1 `U+FBB1` ends print `U+FBD3`). Without the font the page draws `Word.textUthmani` in QPC Hafs after `normalizeFallbackText`.
- Banner and Basmalah are Unicode text in every print (page fonts have no glyphs for them): a double-frame banner with "سُورَةُ" and the name, the Basmalah centred at 62 % width.
- Floating bar: `placeSelectionBar` puts it above the first line, below the last line when the first line is within one bar height of the top, under the first line when below does not fit, centred on the selection, clamped to the screen; it shows after the finger lifts. `ReadIconButton` shows its name in a tooltip on long press. The range feeds `QuranScreenSlots.onPlayRange` and `playPanelRange` (both optional, null falls back to `onPlayFrom` and `playPanel` with the first ayah); copy and share send one line per ayah.
- The ayah panel overlays the Mushaf page: the page keeps its full height and moves up only as far as the selection needs (never more than the panel height); list views shrink to the part above the panel.
- Screen readers: each Mushaf ayah is one invisible node ("Al-Baqarah, ayah 255. Arabic") built 500 ms after the page appears, in reading order, with a long-click action that selects it; the drawn words and rings are `invisibleToUser`. List words and blocks expose click and long-click actions.
- Fills (`PageDecorations`: selected ayahs, playing ayah, playing word, bookmarked ayahs, word states) are drawn behind each line fragment; Hidden words are a 30 % block.
- Frame: surah left, juz right ("Juz 2 · ¼ Hizb 3" only where a quarter starts, from `Quarters`), page number at the outer corner. `showPageInfo` off removes both.
- Page fonts: `FontPackController` (install, remove, status with MB) in `QuranViewModel`. There is no prompt on page loads. On the first Quran screen of a new installation `PrintOfferCard` (over a dimmed page, `FloatingCard`) offers the three prints with sizes from the catalogue; Madani 1421 is ticked, Download sets `ReadSettings.script` and installs it, Not now or Back close it, and once the download runs the card shows progress with Keep reading and Cancel (Cancel restores the earlier page type). The offer is `PrintOfferStore.isPending`: :app sets it when the language screen is answered, so an upgrade never has it (`shouldOpenPrintOffer` also skips a phone with any print installed). A failure shows in the open card, else as a toast; Settings > Mushaf > Print stays the way in. When the print card is handled, `StarterOfferCard` (:app puts it over the Quran screen from `AppPreferences.starterOfferLanguage`) offers the translation and word by word of the language chosen on the first screen (see data.md); Download ticks both, Not now and Keep reading close it for good. Installing or removing any pack drops the loaded layouts and rebuilds the font cache, so the open page redraws in the new print at once.
- Reading page: link rows to the Translations, Transliteration and Word by word lists (value = names shown or Off), a stepper per text layer (`setLayerSizeStep`), Highlight bookmarks and Volume keys switches, and two choice rows for the rotation defaults (Quran pages, Rest of the app; Auto, Portrait, Landscape; they live here because they change how the Quran is read). `PackListKind` lists: ticks show or hide an entry that is on the phone; download, cancel, and remove (confirm dialog naming the entry and the space freed; never for bundled entries). Downloading a translation ticks it, removing unticks it. Transliteration has one layer flag, so a tick there toggles the layer for all entries; word by word and page types are single choice (ticking one uses it, the one in use is not removable). Word by word keeps its layer flag (`showWordByWord`, set from the layers menu; ticking a language also turns it on) apart from `wordByWordLanguage` (null = app language; the Reading row "Meaning language" and the list tick set it; removing the chosen pack resets it). `PageContentLoader` reads that language and falls back to the English pack when the pack is missing and to the English row of a word when the row is blank (v2 packs store '' for English-only words); `QuranViewModel.onAppLanguageChanged` reloads pages because the view model outlives the activity recreation of a language change. Word transliteration comes from the `en_transliteration_words` pack; without it the line view falls back to the whole-ayah `en_transliteration` pack (English only; no Bangla data exists). `translationNameWithNote(name, packId)` (core/ui, `TranslationNotes.kt`) appends the meaning-based note to the Quantum Foundation name by pack id, because the pinned manifest cannot carry it; the Quran screen should call it too.
- Mushaf page: preview of page 50 in the print in use, a Print link row to the Prints list, the Page details switch. The old swipe pager is gone.
- The line-by-line view shows `MissingTranslationPrompt` (one line, Download action, then progress) for the first enabled translation that is not on the phone. Any pack install clears the cached page lists, so a new translation appears at once.
- `FontPackController` is a thin view of `CatalogueModel`, so page fonts download in the background like every other item.
- Font families are cached per font file for the page plus or minus two (`PageFontCache`, one family per file, released when no page in range uses it); see Page below.
- The ayah bar Play button is Play, Pause or Resume (`QuranUiState.playButtonMode`) from the real audio state; starting or resuming clears the selection, pausing keeps the bar. `QuranViewModel.onPlayPressed` calls `AudioPlayer.pause/resume` directly.
- Word cells (`WordsFlow.kt`) align to the top in an RTL FlowRow, Arabic line height 1.6 x size, meaning capped at 2 lines; meanings are matched by word position (`meaningAtPosition`), blank means none. The surah band is accent text without fill; the Basmalah uses the Arabic family.
- Orientation: `quranOrientation` (Auto, Portrait, Landscape) applies while the Quran screen shows and `appOrientation` is restored when it leaves; the rotate item flips the Quran value. Go to page is a `FloatingCard` with soft-filled number fields: it opens focused with the current page selected, the keyboard's Go key does what the Go button does, Bangla digits are read as numbers, and one hint line names a wrong number (`GoToPageResolver.problemOf`). On Mushaf the page slides up while the audio bar shows if the selection sits under it.

- Line-by-line Arabic: for a glyph print (V1, V2, tajweed) every word is a cell drawn by `PageFontWord` in the font of its own page (`AyahWord.glyphs`, found by `GlyphPageIndex` from the page layouts, so an ayah over a page break mixes two fonts), in the night palette at night; the list waits (`rememberFontsLoaded`) until the fonts of its pages are loaded. Other prints keep one Text paragraph, which becomes word cells only while reciting. Recite states are fills behind the cell (`wordCellFill`, same tokens as the Mushaf page); `ListPageEnvironment.wordStates` comes from `reciteWordStates`; while reciting the list scrolls the ayah being recited (`recitedAyah`) into view like the playing ayah, else the fills fall below the screen.
- `PageFontWord`, `rememberFontLookup` and `rememberFontsLoaded` load again when their keys change (produceState keeps its value across keys), so a switch to night repaints tajweed words in the night palette. Floating bars and the word card keep the gap from the screen edges. A problem-word tap on the Mushaf page does not also toggle the bars.
- No font file is read on the main thread: `PageFontCache.load` runs `familyFor` on IO (single file at a time), screens use `rememberFontLookup` / `cachedFamily`, and a Mushaf page draws nothing until both families are known (prefetch also prepares the Hafs family). `MainThreadFontReadTest` fails if `PackRepository.fontFile` is called on the main thread.
- Returning to the screen: `SharedPageFontCache` and `RecentLayouts` (12 layouts, cleared on pack changes) outlive the screen, and `PageMeasureKey` identifies a layout by page, script and item counts, so a page seen a moment ago draws in its first frame. The pager's callbacks and the shift lambda are remembered so pages whose marks did not change skip recomposition on a turn.

- Landscape Mushaf: `pageHeightFor` makes the page `width x 1.5` tall when the body is wider than tall (printed proportions, lines span the width); portrait pages are as tall as the body. `LandscapePageTest` checks line width and overlap at 2392 px.
- Word card: bar colours, placed above the tapped word (`placeSelectionBar`, below it when under the top bar, bottom of the screen when the word's place is unknown); the ayah bar uses the same clearance below the status and top bars (`topBarClearancePx`). Glosses are laid out left to right (`TextStyle.ltr`).
- Word card play: a tap on a word only opens the card (`onWordTapped` never plays). The card heading has the word centred, an add icon at the start corner (`AddToMyWordsButton`: bookmark_add, then bookmark_added filled and not tappable; description Add to / Added to my words) and a 48 dp play icon at the end corner when the word reciter's timings are on the phone (`WordPopup.canPlay`); it plays that word (`playPopupWord`) and shows stop (`isPopupWordPlaying`) until the player is Idle or Error. Timings are the Word audio pack of the reciter (about 3 MB; basfar and raad_al_kurdi have none): the word reciter is `wordReciterFor(chosen, listening, withTimings)`: the Settings > Audio "Word audio" choice (`ReadDependencies.wordReciterId`), else the listening reciter, else the first with timings; root cause of the lost button was the old rule that used only the listening reciter. `QuranViewModel` downloads the word reciter's pack once per screen when `isNetworkMetered` is false (the audio rule), else the card shows `WordAudioOffer` (Download word audio with its size, progress, or the failure with Download again, `downloadWordAudio`). Installing timings does not redraw pages (`changedTimingsOnly`).
- Top bar: when `shouldMoveSettingsToOverflow` (title would get under 112 dp) the settings button is an item of the overflow menu. Layers menu: translations by language then name, the transliteration pack only as its own layer (`layerTranslations`). Text-size rows use fixed label and value columns.

- Print offer card: rows are tick boxes (`PrintOfferState.choices`, V2 ticked at first); Download installs every ticked print, shows the first in card order, and the card closes when all are installed. The layers menu names the word-by-word language ("Word by word · Bangla", `QuranUiState.wordLanguageShown`); the Settings row shows that one language.
- Arabic outside the page (pop-ups, index, search, Learn, recite card) uses `AwnTypography.quran`/`quranLead`, which draw the bundled Uthmanic Hafs from the APK assets; `HafsFont.install` runs in `AwnTheme`, so a style held in a top-level `val` must be a getter.
- Bottom bar (2026-10-22): `bottomBarDisplay(isBusy, areBarsVisible)` gives Full, Mini or None for the audio, recite and Hifz bars; busy = reciting or `QuranScreenSlots.isAudioActive`. A page tap on a busy bar tucks it away (`TuckedAwayWhenHidden`: still composed, no size, since the recite bar exits on dispose) and shows `BusyBarButton` (pause or microphone, bottom start, outside `BottomBarStack` so the lists keep their padding); its tap calls `showBars()`. `enterReciteMode` shows the bars. ## Gotchas
- Tests that build a view model in a field initialiser run before `MainDispatcherRule`; build it lazily.
- `lintRelease` rejects `LocalContext.current.resources.configuration`; use `LocalConfiguration`.
- Material Symbols XML needs its `android:tint` line removed together with care for the closing `>`.
- The recite bar must stop reciting when it leaves composition: Back calls `exitReciteMode`, which only removes the bar.
- Dotted circles: the Quran.com Unicode text has a space before each pause mark (4,362 words); a combining mark after a space has no letter and Android draws it on U+25CC. U+06DE and U+06E9 are symbols, kept; glyph pages are unaffected.

## Tried / rejected
- Recomposition counting of a page in a JVM test: no hook exists without instrumenting production code, so skipping is covered by `highlightsFor` equality tests.
- `ModalBottomSheet` for the translation sheet: replaced by a plain panel, which runs under Robolectric.
- Robolectric text widths do not scale with font size, so geometry is measured a second time at the final size.
- ktfmt rewrites `'۞'` escapes into the raw character; use integer code points for invisible characters.
- Drawing the ۞ sign as a vector: it is a symbol with a real glyph in the font.

## Page (wave 3, page agent)
- A page that cannot be measured is never blank: `measureWithFallback` catches an exception, a non-finite placement or 10 s without a result, logs page and print (tag `PageMeasurement`) and places the Unicode text in the QPC Hafs font; `MeasuredPage` carries the rows and fonts it was placed with. Page 92 (blank on the phone) measured fine for V1, V2 and V4 on all 604 pages with real fonts (`AllPagesMeasureTest`, needs `AWN_DATA_DIR`), so its cause is not in layout or measuring.
- Pages are measured off the main thread: `rememberMeasuredPage` (PageMeasurement.kt) runs `measurePage` on `PageWork.dispatcher` (Default) and keeps the last 5 results in `sharedPageMeasurements`; until ready the page draws nothing. Compose tests must add `InlinePageWorkRule`.
- `PageFontCache.familyFor(script, page, isNight)` caches a family per (script, page, night) over `familiesByFile` (one family per file, so a print with one font for all pages shares one typeface); `retainAround` keeps pages +-2, drops families no page uses, and prepares pages +-2 on IO for the script and mode last asked for. Fonts are `FontFamily(Font(file))`; the typeface itself loads inside the worker's measure.
- Tajweed at night: Android draws CPAL palette 0 only, so `NightFontFiles` writes `night/pN.ttf` beside the font with palette 0 index set to palette 1's (`CpalNightPatch`, checksums kept valid); fonts without a second palette use the original. Night = `!Awn.field.isLight`.
- Size: `planPage` (PagePlan.kt, pure) scales font and slot by `sizeFactor` (`MushafHost.sizeFactor`). While every printed line fits the width (gaps squeezed to 0.04 em) the lines stay and a smaller page is a narrower column, centred, and centred vertically when shorter than the body; else `breakRowsToWidth` (PageLineBreaking.kt) pours the page's words into new lines (end sign stays with its word, banner and Basmalah rows stay, no word splits) and the page scrolls. Factor 1 draws the printed page exactly as before.
- Bars: `BarClearance` (quran/) keeps the tallest height each bar reported through `onSizeChanged` (top bar, audio bar, recite or Hifz bar; floors are status bar plus 56 dp and the 72 dp dock) and gives `PageBarInsets` to every page; the strips are reserved whether the bars show or not. A page that fits sits between the strips; a scrolling page (`MushafPageLayout.kt`) carries the header row, the page and the number row as scroll content with the strips as padding. The line-by-line list uses the measured recite bar height too.
- Memory and speed: `PageMeasurementCache` holds 5 pages, `QuranUiState.layouts/contents` keep pages within 4 of the current one (`keepPagesNear`), pages not on screen are composed `ROWS_REVEALED_PER_FRAME` rows per frame (`revealGradually`, one long frame per swipe before). Phone numbers (6.3 % janky, 188 MB after 30 swipes) are not re-measured yet.
- Word states are soft fills behind the word (`wordStateFills`, tokens `AwnReciteFills`, day family for light fields, night family for dark ones); the ink keeps its colour, Hidden words keep their block.
- `FontDownloadPrompt` shows bar, percent and Cancel (`onCancel`) instead of Download while `progress` is not null. `PageFontWord` draws one word with its page font.
