# Data (:core:data)

## Current state
- Real repositories are wired by `CoreData(context)`; interfaces and fakes are unchanged.
- Only the Arabic text and layout ship in the APK: quran.sqlite (no transliteration column), the Hafs font and the three manifests, in gitignored `core/data/src/main/assets/packs/`. Everything else (translations, word packs, audio, the speech model) is downloaded after install. `:core:data:fetchBundledPacks` copies the files from `awn-data/published/` (a worktree's own folder first, then `$AWN_DATA_DIR/published`) and otherwise downloads them from the data-v1 release; hashes are pinned in `core/data/bundled-packs.sha256`. A rebuilt pack needs its pin updated.
- Unit tests read real translations and word packs from `core/data/build/test-packs/` (`:core:data:fetchTestPacks`, pins in `test-packs.sha256`, same copy-or-download rule); `realPackAssets()` serves them with the bundled files as if all shipped, so those tests do not depend on the APK.
- The per-word transliteration is the pack `en_transliteration_words` (kind `word_transliteration`, table `word_translation`, built by `tools/build_transliteration_pack.py`, first in the Transliteration list). `TranslationRepository.wordTransliteration` reads it; without it the Transliteration layer falls back to the whole-ayah `en_transliteration` text, and shows nothing when neither is on the phone.
- `SpeechModelStore` (core/data/models) downloads the speech model into `filesDir/models` from the models-v1 release: files in `SpeechModelSpec` (size and SHA-256 equal `gradle/models.sha256`, a test compares), `.downloads/<name>.part` resumed by Range, size and SHA-256 checked, then an atomic rename; a failure ends in `SpeechModelState.Failed`. Files already in the folder with the right size count as installed (earlier versions copied them from the APK). The `:speech` process still gets file paths over the binder.
- First launch: after the language answer the Quran screen offers the matching starter download once, after the print card: English `en_saheeh` + `wbw_en` (about 4 MB), Bangla `bn_zakaria` + `wbw_bn` (about 7 MB). New installations tick no translation, transliteration or word meanings (`ReadSettings` defaults); Download ticks the translation and word by word.
- Installed layout under filesDir/packs: `<file>.sqlite`, `fonts/<id>/pN.ttf`, `fonts/qpc-hafs/<file>`; partial downloads in `.downloads/<file>.part` (Range resume, SHA-256 and byte size checked, zip members must be `pN.ttf` and match `member_count`).
- A pack that is bundled (none now) is copied out of the APK on first use and cannot be removed.
- Layouts: V1 uses page_v1/line_v1; V2, QpcHafs and V4Tajweed use page_v2/line_v2; IndoPak throws UnsupportedOperationException.
- One local data folder, `awn-data/` (gitignored, paths in `tools/data_paths.py`): `published/` = exactly the files the app pins, `next/` = the data-v2 workspace, `fonts/` = each print once (zips plus unzipped scripts: build_manifests, verify_packs and AllPagesMeasureTest read the unzipped files; build_fonts.py re-downloads them), `raw/` = source downloads. `AWN_DATA_ROOT` (or `AWN_DATA_DIR`, also read by Gradle) moves the whole folder; `AWN_DATA` names the workspace alone. `tools/migrate_data_layout.py` converted the four old folders.
- Second catalogue (built in awn-data/next, not released; docs/packs.md has the details): IndoPak 15-line (610 pages) and 16-line (548 pages) layout pack plus Nastaleeq font, tajweed Unicode text pack, 31 more translations (each with a terms judgement), 4 more word packs, 28 more reciters (8 with word timings); manifests keep format_version 1 and add optional fields (min_sdk 33 on v4-tajweed).
- Search compares each ayah in three readings of the dagger alef (`DaggerAlefReading`) and tries a waw form of queries ending in alef plus ta marbuta; tests in UthmaniSpellingSearchTest use strings copied from quran.sqlite.
- Banner/bismillah slots are derived: banner at first-word line minus 1 (minus 2 with bismillah_pre). A surah whose first word is on line 2 (18 in V2, 21 in V1) has its Basmalah on line 1 and its banner on line 15 of the previous page; on line 1 it has banner and Basmalah on lines 14 and 15 of the previous page (`readNextPageStarts`). Tested for every surah and script.
- `LineItem.AyahEnd.glyphCode` is the printed end sign in the page font: code of the ayah's last word + 1 (all 6,236 in V2, all but 41 in V1; those end with U+FBB1 and print U+FBD3). Every such code exists in the page fonts (checked).
- `Quarters` (240 rub' al-hizb, first ayah and page in V1 and V2; juz and hizb follow from the number) is generated from Quran.com `rub_el_hizb_number` by `tools/build_quarters.py` into `QuarterData.kt`; a test pins its SHA-256 (09952942...ef37).
- Every pack database has `pack_info.format_version`; `tools/verify_packs.py` fails any that lacks it, and `PackFiles.databaseFormatVersion` rejects it on install as a permanent failure. A download whose SHA-256 differs from the manifest (an old manifest, a replaced release file) is discarded as Damaged and leaves the wanted list, so it does not loop.
- `PackRepository.sizeOf(id)` gives the download bytes (manifest) and the installed bytes (null when not installed).
- User database version 2 adds bookmarked_page, saved_ayah, recent_page (cap 50). The version 1 word `bookmark` table is unused but kept (no drops).
- Storage: every download lives under `filesDir` (`packs/`, `audio/`, `models/`). Nothing uses external or shared storage and the app asks for no storage permission, so phone cleaners that empty external app folders cannot delete a download (the most discussed Quran for Android problem). Cloud backup and device transfer exclude `filesDir`.
- `PackRepository.catalogue()` lists `CatalogueItem`s in manifest order. `CatalogueGrouping` sorts them without naming ids: a font that is not bundled is a PageType; translation kind "word" is WordByWord; kind "transliteration" or an id containing it is Transliteration; kind "ayah" is Translation. A timing pack with `timing_granularity` "word" (alafasy, husary, husary_muallim, minshawi; each about 3 MB) is WordAudio, named after its reciter; Basfar's ayah-level timings, the text and the bundled Hafs font are not items.
- An update is offered when the checksum recorded at install (`packs/.installed/<id>`) differs from the manifest's. A copy with no record (bundled, or installed by an older app) never shows an update.
- `PackSpace`: a database or single font needs the bytes still to download; a font zip needs those plus two more copies of its size (zip and unpacked fonts coexist while unpacking). `install` checks free space first and throws `PackInstallException(reason = NoSpace, neededBytes, freeBytes)`; other reasons are NoInternet, ServerError, Damaged, Other.
- Installs run in WorkManager (`PackInstallWorker`, unique work `pack-install:<id>`, expedited, network required, foreground notification with Cancel). `PackDownloads.request` writes the id to the wanted list (SharedPreferences `wanted_downloads`) first; success or a failure a retry cannot fix removes it, a dropped connection keeps it and retries, and `AwnApplication` calls `resumeWanted` at every start. `.part` files resume by Range.
- `CatalogueModel` (state, space check, install, cancel, remove) is shared by the Reading settings, the Downloads page and `FontPackController`.
- Manifests are read from the bundled JSON only; PackEntry.licence is "Not stated by the source" because manifests carry none.

## Open items
- Nothing from awn-data/next is released: the IndoPak font forbids distribution without written notice from quranwbw.com, 22 packs have no publication permission, and the app's DATA_RELEASE_URL points at data-v1 (tools/write_release_plan.py writes the plan).
- English word-by-word source repeats a phrase on each of its words in surahs 9 to 58 (1,225 rows); `PhraseRepeats` empties the repeats at read time and keeps 4:24:16. The pack is unchanged; rebuilding it with a phrase flag would be cleaner.
- en_asad (Muhammad Asad, tools/build_asad_pack.py, alquran.cloud edition en.asad, whose terms allow republishing translations with the translator named): 22 source errors fixed in CORRECTIONS; asking The Book Foundation (info@thebook.org) later is optional, like the other translations.
- No instrumented test for the asset copy on a device.
- CI and any machine without awn-data/published fetch the pinned quran.sqlite and manifests from data-v1, so the stripped quran.sqlite, the new manifests and `en_transliteration_words.sqlite` must be uploaded there (ops.md).
- Downloads use any network; there is no Wi-Fi-only switch for packs yet (audio has one).
- The 3x space estimate for font zips is 29 MB short for v4-tajweed; the unpack step then fails with NoSpace.

## Gotchas
- `org.json` `optString` returns "null" for JSON null; use isNull.
- HttpURLConnection needs `Accept-Encoding: identity` or Range byte counts break.

## Tried / rejected
- WorkManager's default start-up: it runs before `AwnApplication` has built the services the worker needs; the manifest removes it and the application is the `Configuration.Provider`.
- QUL downloads for IndoPak layouts (login required, no licence text) and the KFGQPC Nastaleeq font site (unreachable from here): not used; Quran.com's qdc API with mushaf=6 and 7 has the layouts.
- Quran.com v4 `mushaf=` parameter: ignored, returns the Madani layout whatever the id.
- Editing the contract `PackEntry` to carry bytes/archive info: not allowed; the catalog keeps a side record per id.
