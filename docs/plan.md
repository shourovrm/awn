# Awn - Quran & Tajweed Helper: project plan

Awn (Arabic عون, "help") is a free, ad-free, account-free native Android app in Kotlin and Jetpack Compose. It shows the Quran page by page, plays reciters word by word, and follows the user's own recitation word by word on the device. An optional on-device tajweed checker (Muaalem) is a future task, out of this round's scope. This plan is current as of 2026-10-20. Figures marked "(estimate)" are guesses, not measurements. Source conventions, build commands and release steps are in `AGENTS.md`.

## Decisions

- Stack: Kotlin, Jetpack Compose, Gradle wrapper, Android only. No code from other Quran apps.
- Application id: `app.awn.quran`. It cannot change after the first Play upload.
- Licence: MIT plus "Awn additional conditions": free to every end user, no ads, no charges, the AI-advisory notice, conditions pass through to forks. The LICENSE text states that the conditions override MIT's "sell copies" wording. The notice (an AI model that may be wrong, for assistance only, not a replacement for a qualified teacher) is required by the Zipformer licence (and by Muaalem's, later) and appears on first launch, in About, in `NOTICE` and in the README, in English, Bangla and Arabic.
- Builds: there are no debug builds. Every build, local or CI, is a signed release build. The keystore lives in GitHub Secrets and in the maintainer's offline backup, and locally in `~/.gradle/gradle.properties` (never in the repo).
- Models and data are hosted in this repository's GitHub Releases under data tags (`data-v1`, `models-v1`), separate from app version tags, so old app versions keep working when new data is published. The Zipformer tracker (NPL-1.2 permits redistribution for free use) is mirrored there with its `tokens.txt` and licence text, which removes the Hugging Face gate from the app, CI and contributors.
- Milestones below are goals, not releases. A release tag `v0.MINOR.PATCH` may close several milestones or part of one. No `1.0` is planned.
- Google Play comes after GitHub Releases. Play needs an app bundle (`bundlePlayRelease`), target API 36 (required since 2026-08-31), and for a new personal account a 12-tester, 14-day closed test. The base module limit is 500 MB compressed.
- Interface languages: English and Bangla. UI text is written from the user's point of view: short, conventional, no explanations, no filler.
- Verification: CI (format, lint, unit tests, JVM tracker tests, build), the headless emulator at `~/android-sdk` (AVD `test`, API 34 x86_64, about 3.2 GB host RAM), and an install on the maintainer's phone over ADB before every push. Measured phone testing on low-end and mid-range devices is a later stage.

## Toolchain

Verified current on 2026-10-20: Gradle 9.8.2, AGP 9.4.1, Kotlin 2.4.21, Compose BOM 2026.09.00, compileSdk and targetSdk 36, minSdk 26, Spotless 8.10.4 with ktfmt 0.65, detekt 1.23.8, Robolectric 4.17, Media3 1.11.1, sherpa-onnx 1.13.8, onnxruntime-android 1.31.0. Versions live in `gradle/libs.versions.toml`.

The machine's `jdk21-openjdk` is corrupt; every Gradle call uses Temurin 21 at `~/.gradle/jdks/temurin-21` (see `AGENTS.md`). CI uses Temurin 21 through `actions/setup-java`, so local and CI builds match.

sherpa-onnx has no Maven artifact. The build downloads `sherpa-onnx-static-link-onnxruntime-1.13.8.aar` (the variant that does not bundle its own `libonnxruntime.so`, which would clash with the ONNX Runtime AAR) from the k2-fsa GitHub release into a gitignored folder, checks its SHA-256, and fails if the hash differs. The same release ships `sherpa-onnx-native-lib-linux-x64-1.13.8.jar`, which lets the tracker run as plain JVM tests on the PC and in CI without an emulator.

## Architecture

- Modules: `:app` (Compose UI, Android services), `:data` (Quran text, word key, packs, Room databases), `:tracker` (pure Kotlin: phoneme source interface, alignment, hifz, skip detection; the sherpa-onnx JNI is the only native dependency and is swapped for the Linux jar in tests), `:player` (Media3 playback, downloads).
- Word key: `(surah, ayah, word_position)` is the one key shared by scripts, timings, translations, tracking colours and bookmarks. A test asserts that the QUL word table, the phoneme reference, every timing file and every word-by-word pack agree on word counts per ayah, with the ayah-end marker rule recorded once.
- Packs: every downloadable pack (script, timing, translation, model) is a file with a `format_version`, a SHA-256 recorded in the manifest, and a credit entry. The app reads any pack whose `format_version` is at or below the version it was built for. Manifests (`scripts.json`, `reciters.json`, `translations.json`, `models.json`) live in the repo and are regenerated by scripts in `tools/` from pinned source downloads, so every pack can be rebuilt.
- User data: Room with forward-only migrations and a test that opens the previous schema. Export and import as JSON through the Storage Access Framework so users keep their data without an account.
- Third-party hosts (QuranicAudio, EveryAyah, QUL) are used for audio at runtime and for data at pack-build time. The app's URL table includes the `.quranicaudio.org` fallback. Cloudflare R2 (free tier, 10 GB, free egress) is the fallback host if a source disappears.

## Spikes before the schedule is trusted

One one-day experiment replaces the largest guess in this plan and runs right after milestone 1.

Zipformer on the JVM: a JUnit test on the PC loads `zipformer_p_arabic_v3.int8.onnx` and `tokens.txt` through the Linux sherpa-onnx jar with `OnlineZipformer2CtcModelConfig`, feeds Husary 1:1 as 16 kHz PCM, and prints each token with its timestamp. It settles the phoneme accuracy against the reference, the timestamp granularity, the latency per chunk, and whether timestamps are enough for a madd estimate.

## Milestone 1: skeleton

Goal: a signed, installable, empty app with CI, licence and the first-launch notice.

Steps: generate the Gradle project with the versions above, product flavors `github` (in-app update check against GitHub Releases) and `play` (no self-update), R8 on, ABI splits for arm64-v8a, armeabi-v7a and x86_64 (the emulator needs the last; drop it from published builds later), `versionName` and `versionCode` derived from the git tag as `MAJOR*10000 + MINOR*100 + PATCH`, with a per-ABI offset of 1 to 3 added in the millions place and a fallback of `0.0.0` plus commit count on untagged builds. Write LICENSE, NOTICE, README (install, run, test, verify-signature fingerprint), `.editorconfig`, Spotless, detekt, Android Lint with `warningsAsErrors`. Add the AAR download task and the models download task. Add the first-launch notice screen, blocking until "I understand", reachable from About. Add the four workflows from `AGENTS.md`.

Exit check:
```
./gradlew spotlessCheck detekt lintGithubRelease testGithubReleaseUnitTest assembleGithubRelease   # exit 0
./gradlew installGithubRelease && adb shell am start -n app.awn.quran/.MainActivity && sleep 60 && adb logcat -d '*:E' | grep -c 'FATAL EXCEPTION'   # prints 0
```
Time: 1 to 2 weeks part-time (estimate).

## Milestone 2: read

Goal: the whole Quran readable in several scripts, with bookmarks and translations.

Inputs: QUL word tables, layouts and fonts (`qul.tarteel.ai/resources/quran-script`, `/mushaf-layout`, `/font`): QPC Hafs Unicode (bundled in the APK); downloadable packs for QPC V1 (1405H print, 604 pages), QPC V2 (1421H print, 604 pages, the current Madani Mushaf), QPC V4 tajweed (1441H print, coloured tajweed glyphs), and IndoPak Nastaleeq with the KFGQPC 15-line layout (610 pages) plus the Taj 13-line layout (847 pages). QUL has no tajweed-coloured IndoPak font or script, so IndoPak ships without tajweed colours. Pack sizes are measured at the first pack build; V2 and V4 are the priority. Translations: English from QUL (The Clear Quran by Dr. Mustafa Khattab, Abdul Haleem, Saheeh International; the first two are copyrighted texts that QUL hosts and Quran.com ships, credited verbatim), other languages from the QuranEnc API (`quranenc.com/api/v1/`, 76 translations, no Bangla or Malay), Bangla: QUL's Dr. Abu Bakr Muhammad Zakaria (default) and Quantum Foundation's rendering (text supplied by the maintainer, who handles permission). Malay: Tanzil Basmeih (non-commercial, link back). Word-by-word: QUL English and Bangla. Transliteration: QUL English transliteration (ayah by ayah with markup, and word by word); Bangla transliteration does not exist as data anywhere, so a `tools/` script generates it rule by rule from the Arabic letters and the per-word phoneme reference, and the pack is labelled as generated.

Steps: import the QUL word table into a bundled SQLite file keyed by the word key, with page and line; page view in Compose, one row per line, right to left, each word tappable with a colour state (neutral, green, yellow, red, hidden); navigation by swipe, surah, juz and page; `Script` record (font, word table, layout, line count) with glyph scripts loading one font per page, cached five pages either side; script picker with page previews; translation packs (one SQLite per translation with `surah, ayah, text, version, source_url`, a `TERMS.md` quoting the source's conditions, and the source checksum) shown under each ayah, word-by-word on long-press; Saheeh International and Zakaria bundled, others downloaded from the data release; bookmarks, saved ayahs with notes, recent pages (capped at 50), export and import.

Exit check (CI and emulator):
```
./gradlew :data:testGithubReleaseUnitTest --tests '*ScriptRenderTest*'      # renders every page per script: missing glyphs = 0, word counts equal the table
./gradlew :data:testGithubReleaseUnitTest --tests '*TranslationPackTest*'   # 6236 non-empty rows and matching checksum per pack
./gradlew connectedGithubReleaseAndroidTest --tests '*PersistenceTest*'     # 10 bookmarks, 10 saved ayahs, 10 recent pages survive force-stop; export re-imports 30 rows
```
IndoPak layouts have other page counts; the test uses each layout's own count. Time: 6 to 8 weeks part-time (estimate).

## Milestone 3: listen

Goal: reciters play by page, surah or word, with downloads kept on the device.

Inputs, verified HTTP 200 on 2026-10-20:
- Surah files: `https://download.quranicaudio.com/quran/<path>/<SSS>.mp3`, paths from `https://quranicaudio.com/api/qaris` (177 entries): Husary `mahmood_khaleel_al-husaree/` (id 16), Husary Muallim `husary_muallim/` (141), Alafasy `mishaari_raashid_al_3afaasee/` (5), Minshawi `muhammad_siddeeq_al-minshaawee/` (6), Basfar `abdullaah_basfar/` (2), Raad al-Kurdi `raad_mohammad_al_kurdi/mp3/` (168).
- Ayah files: `https://mirrors.quranicaudio.com/everyayah/<folder>/<SSS><AAA>.mp3`, folders from `https://everyayah.com/data/recitations.js`: `Husary_128kbps`, `Husary_Muallim_128kbps`, `Alafasy_128kbps`, `Minshawy_Murattal_128kbps`, `Abdullah_Basfar_64kbps` and `_192kbps`. Raad al-Kurdi has no ayah files on any host.
- Fallback: replace `.quranicaudio.com` with `.quranicaudio.org` (verified 200).
- Timings from QUL (`qul.tarteel.ai/resources/recitation`, 133 recitations, 59 with segments): Husary murattal id 110, Husary Muallim id 112 (id 112 is the Muallim set, not the murattal one), Alafasy murattal (the only set tagged with word segments), Minshawi murattal ayah-by-ayah, Basfar surah-by-surah. Formats: `[word_position, start_ms, end_ms]` per ayah file, or `timestamp_from`/`timestamp_to` keyed `surah:ayah` for surah files. Raad al-Kurdi has no timings: surah playback only.

Steps: `reciters.json` with both URL patterns, the QUL file, the EveryAyah folder it was timed against, a `verified` flag, and a `word_by_word` flag (true for Alafasy, Husary murattal, Husary Muallim and Minshawi murattal; Basfar and Raad al-Kurdi are listening only); download the current page's ayah files by default or the whole surah on request, with OkHttp, Range resume and a per-reciter size in Settings; Media3 playback with ayah highlighting, word tap seeks to `start_ms` and stops at `end_ms`, repeat word or ayah N times; a PC script that, per reciter, cuts 20 random words by the QUL timing from the ayah file and has the Zipformer transcribe each cut, setting `verified` only when at least 18 of 20 match the reference phonemes.

Exit check:
```
python tools/verify_timings.py --reciter <id>      # prints matched=N/20, N >= 18 for every verified reciter
./gradlew connectedGithubReleaseAndroidTest --tests '*PlaybackTest*'   # page 1 download survives restart; .org fallback used when .com is blocked
```
If a reciter fails: try the other bitrate folder (encoder delay differs by up to 50 ms), else ship it with ayah-level playback and no word seek. Time: 4 to 5 weeks part-time (estimate).

## Milestone 4: recite

Goal: the app follows the user's recitation word by word, with a hifz mode that hides words and flags skips.

Inputs: `zipformer_p_arabic_v3.int8.onnx` (72,705,392 bytes, 65.5 M parameters, streaming zipformer2 CTC), `zipformer_p_arabic_v3.1.int8.onnx` (madd fine-tune, same interface), `tokens.txt` (251 symbols, blank is ID 250), `quran_text2phoneme.json`, `ordered_quran_phonemes.json`, all from `huggingface.co/Quran-Lab/zipformer_p-arabic-v3` (gated; downloaded once by the maintainer and mirrored in the `models-v1` data release with the NPL-1.2 text). Input is 16 kHz mono with 80-dim Kaldi fbank, Povey window; the export takes 48 fbank frames (0.48 s) per chunk and the chunk size cannot be changed without re-exporting. sherpa-onnx returns, per emitted token, the symbol, its onset timestamp and its probability; it does not expose per-frame posteriors. The model card warns that it tends to transcribe the correct rule rather than the deviation (canonical bias), and that madd lengths are unreliable in the token stream.

Test audio: Husary ayah files for surahs 1, 112, 113 and 114 (22 ayahs, 87 words), surahs 2 ayahs 1 to 20 and 36 ayahs 1 to 20 for long-ayah coverage, and the maintainer's own recordings of the same ayahs, converted with ffmpeg to 16 kHz mono WAV. Negative fixtures: each surah with one ayah cut out, and each with one foreign word spliced in.

Steps:
1. Phoneme reference: convert the two JSON files into a per-word phoneme table keyed by the word key; test that all 6,236 ayahs have a reference and word counts match the QUL table.
2. Audio capture: `AudioRecord`, 16 kHz mono 16-bit, `VOICE_RECOGNITION` source, 100 ms blocks into a `TrackerInput` interface; a WAV implementation drives every test.
3. Phoneme source: sherpa-onnx `OnlineRecognizer` with `OnlineZipformer2CtcModelConfig`, greedy search, `enableEndpoint = false` (the default endpoint rule cuts the stream at 20 s), emitting (symbol, timestamp, probability).
4. Alignment: dynamic-programming alignment (Needleman-Wunsch, affine gaps) of the growing token sequence against the reference phonemes of the current and next two ayahs, anchored to the last confirmed word; green when at least 80 % of a word's phonemes align with at most one substitution, yellow when partly covered, red when two or more substitutions. Re-anchor by searching the surah when 12 consecutive tokens fail to align.
5. Speed control: a continuous slider in the recitation screen maps to the alignment's patience (how many unmatched tokens before re-anchoring, how much of a word must be heard before it turns green, the time before the next word is expected). It replaces the three fixed presets other apps offer.
6. Skip and insert detection: a reference-side gap covering a whole word marks it skipped; six or more unmatched hypothesis tokens mark an insertion at the preceding word.
7. Hifz mode: hide a chosen range, reveal each word when confirmed, flag skips, first-letter hint.
8. Madd estimate (experimental, not in the exit check): the gap between a long vowel's onset timestamp and the next token's onset, compared with the reciter's median haraka length in the current ayah. Spike 1 decides whether this is usable; forced alignment with per-frame posteriors is the later alternative.

Exit check (JVM tests in CI on the Linux jar, repeated on the emulator):
```
./gradlew :tracker:test --tests '*TrackingFixtureTest*'
# green words >= 83 of 87 on the four short surahs and >= 95 % on the two long-ayah sets, wrong-ayah anchors = 0
# skips flagged in >= 9 of 10 cut fixtures, false skips = 0 on 10 unmodified fixtures
# spliced word flagged as insertion or red in >= 7 of 10 fixtures (canonical bias makes substitution detection weaker; skip detection is the measured feature)
./gradlew connectedGithubReleaseAndroidTest --tests '*HifzScreenTest*'   # hint, colour mapping, slider persistence
```
Postponed phone check: word latency under 1.0 s median on a mid-range phone, model load under 3 s. If tracking fails: confirm the WAV seam delivers 16 kHz mono (a resampling mismatch halves accuracy silently), try v3.1, tune the step 4 thresholds on the fixtures before changing the algorithm. Time: 8 to 12 weeks part-time (estimate), the largest item in the plan.

## Milestone 5: learn

Goal: progress, revision and a tajweed guide.

Steps: record events (page opened, ayah tracked green, ayah completed in hifz without a skip); daily streak, pages per day, memorised ayahs (three skip-free hifz completions on three days, user-adjustable); FSRS scheduling (Free Spaced Repetition Scheduler, the algorithm Anki uses) ported to Kotlin from py-fsrs, with fuzzing disabled, and a Revision screen of cards due today; a Progress screen; a tajweed guide of 12 to 16 lessons in English and Bangla (makharij overview, sifat, noon and meem sakinah rules, ghunnah, qalqalah, madd types, tafkheem and tarqeeq, waqf signs), each with three examples pulled from the QUL tajweed-marked text so highlighted letters come from data; 60 to 100 daily snippets (Quran ayahs about recitation, and hadith graded sahih in Bukhari or Muslim) in `assets/snippets.json` with reference, grade and URL, Arabic text plus the project's own short English and Bangla renderings.

Exit check (CI):
```
./gradlew :data:test --tests '*FsrsReferenceTest*'    # 200 of 200 next-due intervals equal py-fsrs to the day
python tools/check_snippets.py                         # 100 % of URLs return 200 and the hadith number matches
python tools/check_lessons.py                          # 100 % of examples carry the lesson's tajweed tag in QUL data
```
Time: 6 to 9 weeks part-time (estimate).

## Later

- Muaalem tajweed checker (beta): an optional 876 MB on-device download (`huggingface.co/Abddar/muaalem-v3-2-int8-android-onnx`, 11 CTC heads, inputs `input_features` and `attention_mask`, QML-1.0 conditions apply) that points out likely tajweed mistakes per word. Planned as its own task with its own spike, evaluation harness, Kotlin feature extractor and precision gate; nothing in milestones 1 to 5 depends on it, and the per-word colour states and word key are the only hooks it needs.
- Google Play publication with the `play` flavor and the same signing key uploaded to Play App Signing with a separate upload key.
- Measured phone testing on a 3 GB and a 6 GB device: load time, RAM, word latency filmed at 60 fps, battery over 20 minutes.
- Quranic Arabic lessons from QUL's morphology tables (the Quranic Arabic Corpus download is GPL and is not bundled).
- Mini model track (never blocking): a width-sliced w2v-BERT 2.0 student of about 120 M parameters distilled from Muaalem logits on `obadx/muaalem-annotated-v3` (848 h, 97 GB), trained on Kaggle, budget $0 to $20. Gate: per-error-type F1 within 5 points of the teacher. If obadx releases `muaalem-model-v3-mini`, evaluate it first.
