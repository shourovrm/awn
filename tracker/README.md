# :tracker

Pure Kotlin JVM module (no Android dependency) that follows a recitation word by word. Audio goes
through `SherpaPhonemeSource` (sherpa-onnx, streaming Zipformer CTC) to phonemes; `AlignmentTracker`
aligns them to the reference phonemes of the surah and reports `TrackerEvent`s.

## Run and test

```
JAVA_HOME=~/.gradle/jdks/temurin-21 ./gradlew :tracker:fetchFixtures   # test audio, needs ffmpeg
JAVA_HOME=~/.gradle/jdks/temurin-21 ./gradlew :tracker:test            # also fetches libs, model, fixtures
```

`fetchFixtures` downloads Husary ayah MP3s from EveryAyah into the gitignored `tracker/fixtures/`
and builds 16 kHz mono WAV recordings: `full_*` (6), `cut_*` (10, one ayah left out), `splice_*`
(10, one foreign word added) and `stretch_*` (4 surahs at 1.2 times speed, plus ayah 1:1 at 0.8 and
1.2 for `tools/spike_zipformer.md`). `TrackingFixtureTest` decodes each recording with the real
model and caches the phonemes in `tracker/fixtures/events/`; delete that folder to decode again.

## Reference file: `ordered_quran_phonemes.json`

Generated by quran-transcript, schema 2, 12.8 MB, from the Quran-Lab Zipformer release. Fields the
code relies on:

- `schema`: must be 2; `JsonReferencePhonemes` refuses other values.
- `verses`: object with 6,236 entries keyed `"surah:ayah"`.
- `verses[key].aya_phonemes_list`: one string per spoken word, in order. The word count equals the
  count of space-separated words in `aya_text` for all 6,236 ayahs. Each character of a string is one
  phoneme: consonants, short vowel marks, a doubled letter for a shadda (`للَ`), a repeated letter
  for a lengthened vowel (`ۦۦۦۦ` is a madd of four counts) and `ڇ` for a pause-form tanween.
- The phonemes already contain the recitation rules (idgham, ikhfa, madd lengths for `moshaf`
  settings), so they differ from the written text; the ayah is spoken as if stopped at its end.

Fields that exist and are not used: `aya_phoneme` (the words joined), `aya_text`, `aya_ui`,
`spans` (base 36 digits, see `span_digits`), `rules` (triples that look like
`[position, rule id, length]` with ids from `rule_names`, 1 natural madd to 8 qalqalah), the
`moshaf` settings and the surah names.

All 41 distinct characters in the reference are one-character symbols in `tokens.txt`; the model's
251 symbols add 208 two- or three-character symbols (and `<blank>`) such as `بَ` and `ررَ`, which are sequences of
those characters. The tracker therefore compares single characters, not model tokens.

`ref_norm_ph.txt` is one line of 311,886 characters with no separator between words or ayahs. It is
the phoneme string of all 6,236 ayahs in order (652,401 characters in the JSON) with the short
vowel marks removed and doubled letters and madd runs shortened (1:1 becomes `بسملاهرحمانرحۦم`).
It does not equal a simple mark removal plus run merge of the JSON (the two differ from the 22nd
character on, at 1:2), so its generator is unknown; it looks like the consonant skeleton used to
score or train the model. Awn does not use it.

## Madd annotations

`rules` holds `[position, rule id, length]` triples; the positions index a string that is not in
the file, so they are ignored. The triples with ids 1 to 6 (natural, monfasel, mottasel, mottasel at
pause, aared, lazim; 7 is leen, 8 qalqalah) come in the order of the lengthened vowels, which are the
runs of two or more `ا`, `ۥ` or `ۦ` in the word phonemes, and the length equals the run length (the
counts come from the `moshaf` header, for example `madd_monfasel_len` 4). `JsonReferencePhonemes`
pairs them and puts them on `ReferenceWord.madds`; for 10 of 6,236 ayahs (muqatta'at, leen madd) the
two lists disagree and the ayah gets no annotations.
